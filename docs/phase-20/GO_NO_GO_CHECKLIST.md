# Checklist GO / NO-GO

## Negocio

- El propietario confirma ventana, alcance y canal de contacto.
- Existe una persona disponible para decisiones durante la ventana.

## Técnica

- El release corresponde al paquete aceptado.
- El objetivo de rollback existe y es identificable.
- El plan de hostname coincide con el sitio y tenant.

## Operaciones

- Los SLO están definidos y la telemetría está disponible.
- Existe responsable del incidente y ruta de escalamiento.
- La ventana permite completar canary y rollback.

## Privacidad

- Finalidades, contacto público y aviso no cambiaron desde la aceptación.
- No aparecen nuevos formularios, trackers o destinatarios.

## Regla

Un NO-GO bloquea el plan. La corrección requiere una revisión nueva; la decisión previa no se edita.
